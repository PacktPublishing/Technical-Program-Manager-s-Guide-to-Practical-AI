# Workflow: Program Closure

**Stages:** 4
**When to run:** Final 2 weeks of a program
**Output:** Closure Checklist + Program Summary + Memory + Retro
**Mid-entry:** Yes — start at any stage

---

## Overview

Program closure is often rushed or skipped. This workflow makes it systematic. It ensures nothing falls through the cracks operationally, captures institutional knowledge before the team disperses, and produces the artifacts that justify the program's existence for future reference.

```
Stage 1: /tpm-programclosure    → Systematic closure checklist
    ↓   [Output: Signed-off Closure Checklist]
Stage 2: /tpm-programsummary    → Final narrative of outcomes and impact
    ↓   [Output: Final Program Summary]
Stage 3: /tpm-programmemory     → Capture institutional knowledge
    ↓   [Output: Program Memory Document]
Stage 4: /tpm-programretro      → Team retrospective
    ↓   [Output: Retro Analysis + Action Items]
```

---

## Stage 1 — Program Closure Checklist

**Skill:** `/tpm-programclosure`
**Goal:** Ensure all operational, technical, and stakeholder items are closed

**Inputs needed:**
- Program name and end date
- Teams involved
- Outstanding items

**Key output to carry forward:** Outstanding items list → identifies what needs to be addressed before Summary is final

**Gate:** All checklist items completed and signed off

---

## Stage 2 — Program Summary

**Skill:** `/tpm-programsummary`
**Goal:** Write the definitive record of what was built, what was achieved, and what was learned

**Inputs needed:**
- Original program charter (objectives, success metrics)
- Closure checklist (Stage 1)
- Actual delivery scope and metrics

**Key output to carry forward:** What went well / didn't / decisions → feed into Memory and Retro

---

## Stage 3 — Program Memory

**Skill:** `/tpm-programmemory`
**Goal:** Capture knowledge that lives only in people's heads before the team disperses

**Inputs needed:**
- Program Summary (Stage 2)
- Key team members to interview
- Critical decisions and surprises from the program

**Output:** Program Memory document archived in Confluence

---

## Stage 4 — Retrospective

**Skill:** `/tpm-programretro`
**Goal:** Facilitate a structured team retro that produces actionable improvements

**Inputs needed:**
- Program Summary (Stage 2)
- Program Memory themes (Stage 3)
- Teams participating

**Output:** Retro Analysis with owners action items and org escalations

---

## Workflow Complete

**Artifacts produced:**
1. `Program Closure Checklist` — Signed off, archived
2. `Final Program Summary` — Outcomes, impact, learnings
3. `Program Memory` — Institutional knowledge preserved
4. `Retrospective Analysis` — Actionable team improvements

**Archive checklist:**
- [ ] All artifacts saved to Confluence program space
- [ ] Jira program board archived
- [ ] Slack channel archived or repurposed
- [ ] TPM moves to next assignment

**Duration:** ~1 week from start to complete
