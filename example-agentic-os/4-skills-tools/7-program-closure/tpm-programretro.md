# /tpm-programretro — Retrospective

**Lifecycle Stage:** Program Closure
**Job-to-be-Done:** Facilitate a program-level retrospective — what worked, what didn't, and what to carry forward as actionable team improvements

---

## Instructions

Read `domain-context.md` and `personal-context.md` before starting.

A program retro is not a sprint retro. It operates at a longer time horizon, involves more teams, and produces org-level improvements, not just team tweaks.

---

## Interaction Flow

**Step 1 — Intake**

1. Program name and duration
2. Teams participating in the retro
3. Format: facilitated session (generate agenda + activities) OR async (generate survey + analysis)
4. Key events, incidents, or challenges from the program
5. Any pre-retro feedback already collected
6. Time available (30min / 1hr / 2hr)

**Step 2 — Generate**

---

## Mode A: Facilitated Session Prep

```markdown
# Retro Facilitation Guide: [Program Name]

**Duration:** [X minutes]
**Participants:** [Teams/roles]
**Facilitator:** [TPM name]
**Format:** Remote / In-person

---

## Agenda

| Time | Activity | Format | Goal |
|------|---------|--------|------|
| 0:00 | Welcome + ground rules | Facilitator | Psychological safety |
| 0:05 | Timeline walk | Group | Shared memory |
| 0:20 | What went well | Silent writing + share | Amplify strengths |
| 0:35 | What didn't work | Silent writing + share | Surface pain |
| 0:50 | Root cause: top issue | Group discussion | Go deep on one thing |
| 1:05 | Action items | Group | Commit to change |
| 1:15 | Close + appreciation | Facilitator | Energy + closure |

---

## Timeline Walk Prompts

[List 5–8 key program moments to display for the group — kickoff, major decisions, blockers, launches, incidents]

---

## Retrospective Questions

**What went well?** *(Start: do more of this)*
- What decisions are you glad we made?
- What process or practice saved us?
- Which team collaboration moments were effective?

**What didn't work?** *(Stop: change or eliminate this)*
- Where did we lose time unnecessarily?
- What process created friction?
- What did we know was wrong but didn't address fast enough?

**What should we try?** *(Experiment: something new)*
- What would you do differently for the next program?
- What practice from another team should we adopt?
```

## Output Format

Determined by mode:

| Mode | Emits |
|------|-------|
| **A — Facilitated Session Prep** | Agenda, timeline walk prompts, and the retrospective question set — a runnable session plan |
| **B — Retro Analysis** | Themes Identified, Action Items (with owners), What to Carry Forward, and the Retro Health Score table |

Both modes end with named owners on every action item. A retro that produces
themes but no owners is not complete.

---

## Design Principles Applied
- Delivery First: Retro output is actionable improvements, not feel-good sessions
- Cross-Team Alignment: Program-level retro includes all teams, not just one squad
- Risk Visibility: Systemic issues escalated, not buried
